# 思源笔记 iPad「随手写」（Scribble）空块无法输入修复

一个思源笔记（SiYuan）的 JS 代码片段，用于修复 iPad 上「随手写」在**空段落 / 空标题**里写不出字的问题。

## 问题现象

- iPad 上用 Apple Pencil 的「随手写」功能，笔尖落在**新建的空段落/空标题**上时写不出任何字；
- 先用屏幕键盘敲一个字之后，同一段落里再手写就恢复正常；
- 已解决的连带问题：连续手写时字母顺序错乱（例如「你好」变成「好你」）。

## 原因

随手写要把笔迹转换进「**已有文本节点 + 光标**」的可编辑区域。新建的空段落只有 `contenteditable` 容器、没有任何文本节点，笔尖落下时系统拿不到插入点，因此写不出字；只要用键盘敲一个字，容器里就有了文本节点，随手写于是恢复正常。

## 使用方法

1. 打开思源：**设置 → 外观 → 代码片段 → JS**；
2. 点「新建」，把 [snippet.js](snippet.js) 的全部内容粘贴进去；
3. 将片段命名为「修复iPad「随手写」(Scribble) 空块无法输入bug」并**启用**（打开右侧开关）；
4. 在代码片段面板点「重新加载」（或重启思源）使其生效。

## 它做了什么

| 触发时机 | 处理 |
| --- | --- |
| 光标进入空段落/空标题（点按、回车新建、键盘聚焦） | 在可编辑容器里放入一个零宽空格（U+200B）文本节点作为书写锚点，并把光标放进这个文本节点 |
| 笔尖按下空块（`pointerdown` / 笔的 `touchstart`） | 补锚点并聚焦，抢在思源的触摸光标逻辑之前 |
| 块已在编辑状态 | **绝不再动光标**。手写两笔之间文字可能还没提交，此时重置光标会把后写的字插到前一个字前面 |
| 文字真正插入前（`beforeinput` / `compositionstart` / `keydown`） | 先清掉零宽空格——此时还没有待提交的标记文本，不会打乱输入顺序 |
| 失焦 | 删除残留的空节点，恢复思源原本的空块 DOM（占位提示依赖 `:empty`） |

## 说明

- 只在 iPad 上生效：iPadOS 13+ 的 UA 是 `Macintosh`，靠 `navigator.maxTouchPoints > 1` 识别；其他设备直接跳过，不产生任何影响。
- 自带重复注入保护（`window.__syIpadScribbleFix`），片段被重复加载也只会执行一次。
- 只处理 `.protyle-wysiwyg` 里的 `NodeParagraph` / `NodeHeading`，跳过表格、数据库、标题栏、渲染块等特殊区域。
